Set this repository's site up with Tonen, so people can comment on it while it runs.
Your member may not be a developer: before each step, say in one plain sentence what you're about to do and why; never ask them to run a command; when their browser opens, tell them what to click there; and end with what they can do now.
1. Look first: what the site is built with, and the address its dev server runs at. Call `tonen_cli` with `status`: whether this computer is signed in to Tonen, and whether this repository has a project already.
2. Call `tonen_cli` with `init` and the dev server's address as `site` (or the deployed one, when there's no dev server), each address whole, with the folder it's published under. Its first call may open their browser to sign in to Tonen: tell them. It names the project in tonen.json at the repository's root: tell them to commit it, so their team and Claude find the project too. Add the script tag where the answer's `install.where` says, unless `edited` names the file it went into, always, also when the site only runs on this computer: a teammate who runs it gets the bar too, and sees only their own comments there. Add the CSP sources if the site sets a Content-Security-Policy. On localhost anyone who opens it can comment, on every port. For an address that isn't this computer, ask them once whether people outside their team use it for real and pass their answer as `access` (yes: `people`, where only the people they add can comment; no, such as staging, a prototype or a preview: `anyone`, where anyone who opens it can, after confirming their email). For every other deployed address (a preview, the production domain), `tonen_cli` with `sites_add`, asking the same. If they already have a project for this site on Tonen, `tonen_cli` with `link` and its id instead of `init`.
3. Each deployed address waits for them to confirm it, and until then Tonen doesn't run there: give them the Setup tab's link, ask them to confirm it now in their browser, and call `tonen_cli` with `projects` until it no longer waits before you say it's done.
4. Start the dev server if it isn't running, then call `share_local_site` with its port, so people elsewhere open it too: only the people they add get in, and anyone with the local site's own share link, which they make on the Setup tab. The first time, their browser opens to confirm sharing: tell them.
5. Tell them, in a few short lines: open the shared address (it signs them in with one click) and press C to comment on anything; that the same address works for the people they add, while this session runs; and what's next: /tonen:add-reviewers asks people to comment by email, and /tonen:fix works through what they comment. The first time they want comments fixed, or @Claude to answer them on the site, Claude Code asks them to sign in to Tonen once: they type /mcp, pick Tonen, then Authenticate.
